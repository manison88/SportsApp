# Onboarding after Welcome: 3 pages, 3 variants (24 screens)
Flow (all variants): Page 1 problem, Page 2 solution, Page 3 access then scan = 3a priming, 3b iOS alert, 3c scanning, 3d first result. Fallback sheets: denied, nothing found. No account, no questions. Pages 1-2: one hero, one button, 3 dots, Skip top right. Skip on 1/2 jumps to 3a; Not now on 3a goes to Explore sample games.
Shared copy. 3a: "Witness reads dates and places. Nothing else." Reads: when / where it was taken. Never leaves this iPhone: your photos, dates, places, results. Buttons: Allow photo access / Choose photos instead / Not now. 3b purpose string: "Witness reads the date and location of your photos on this iPhone to find the games you attended. Photos are never uploaded." Buttons Limit Access... / Allow Full Access / Don't Allow. 3c: "12,486 of 40,126 photos checked", 318 near a stadium, 9 venues, 21 games matched, rolling venue list (newest on top, NEW tag, sport-colored bar), "This can take a few minutes. You can leave and keep using the app.", Keep going in background. 3d: "47 games found", newest game hero, Review games, "Found on this iPhone. Nothing was uploaded." Denied: "Photo access is off" (Open Settings, Choose photos, Add a game by hand, Explore sample games). Empty: "No games found yet" (Choose another album, Add a game by hand, Explore sample games).
## A Typographic (features/a-typographic)
Idea: type is the hero, a dimmed 8-col photo grid is texture. P1 "40,000 photos. How many games?" / "Somewhere in there is every game you went to. Nothing in it says which." / Next. P2 "One photo. One game." / "Witness reads each photo's date and place, matches it to the real schedule, and you confirm." / Continue. 3a is a ledger (Date, Place, Content: Not read). 3c giant counter. 3d giant "47".
Motion: P1 grid tiles fade in with 12ms stagger from random order, then grid drifts up 8pt over 6s linear (slow). P2 lit tile pulses once (amber glow, 400ms ease-out), the amber stem draws down 250ms, card rises 24pt + fades in 450ms spring(0.85), headline fades 200ms later. 3c counter uses contentTransition(.numericText) every 0.5s. Reduce motion: no drift or stagger, crossfade 150ms, card appears in place.
Risk: P1 is a question with no visual proof; strongest on 40k libraries, weaker for small ones. Cost: low. Grid = LazyVGrid of 100 cached thumbs, one card (reuse game card), ledger rows new.
## B Mess to order (features/b-mess-to-order)
Idea: show the mess, then the order. P1 "Your games are buried in there." / "40,126 photos, and none of them say which game it was." / Next. P2 "Sorted by the real schedule." / "Each photo's date and place is matched to an actual game, in order. You confirm." / Continue. 3c adds a strip of thumbnails, lit ones are the matches. 3d stacked tickets, "47 games found."
Motion (P1 to P2, 1.4s, triggered when page 2 becomes active): the 16 scattered photos start at their P1 positions and rotation. Step 1 (0-300ms, easeOut) all photos settle to rotation 0. Step 2 (300-1100ms, spring response .55 damping .82, 40ms stagger by date) the 4 matched photos fly to their ticket thumbnail slots via matchedGeometryEffect; the ticket body (venue, score) wipes in 200ms after landing. Step 3 the 12 unmatched photos shrink to 0.3, fade to 0.35 and drift off the top. Year labels fade in last. Reduce motion: no flight, P2 shows the sorted state with a 200ms crossfade from the pile.
Risk: the most delightful but the P1 pile is less legible at small sizes, and the motion must read in 1s or users tap Next past it. Cost: medium-high. matchedGeometryEffect across TabView pages is fragile; use one shared canvas view that owns both layouts and a progress value driven by page offset (ScrollView + scrollTransition is easiest).
## C Before / after (features/c-before-after)
Idea: a camera roll mock the user recognizes. P1 "Dates. No meaning." / "Every photo knows when it was taken. None of them know which game it was." / Next. P2 "Witness finds the games." / "It matches photo dates and places to the real schedule. You confirm." plus rows Timeline "Every game, in order", Map "Everywhere you watched", Passport "Stadiums you visited" / Continue. 3a mini roll behind a lock. 3c a 24-cell grid fills in, 3d three count tiles (Timeline 47, Map 14, Passport 14).
Motion: P2 non-game tiles dim to 35% over 500ms easeInOut, game tiles get a sport-colored ring (200ms) and a check pops (spring), two cards slide up 20pt and settle with 3 degree rotation, 120ms stagger, benefit rows fade in 60ms apart. Reduce motion: final state with 150ms crossfade.
Risk: P2 is dense (grid, 2 cards, 3 rows) so it is the likeliest page to be skimmed; it explains the whole product at once. Cost: medium. Needs a fake roll (bundled thumbs plus junk tiles, no real library data), benefit rows are plain views.
## Engineering notes (all)
TabView(.page) with indexViewStyle hidden and custom dots, Skip sets selection = 2. Page 3 is a state machine: priming, requesting, scanning, result, denied, empty. PHPhotoLibrary.requestAuthorization(for: .readWrite) after the Allow tap; .limited continues the scan on the selection and shows a Manage banner later; .denied shows the sheet (Open Settings via UIApplication.openSettingsURLString; recheck on scenePhase == .active); Choose photos instead uses PhotosPicker without needing full access. Scan: existing scanner with a progress publisher (checked, total, nearStadium, venues, matched), real counts only. Background: keep running on a Task while foregrounded, register a BGProcessingTask for continuation and persist a cursor so it resumes after scenePhase changes. Reuse: existing game card, team chips, Review list, WelcomeView CTAs for Explore/Add by hand. New: scan progress view, bottom sheets, purpose string in Info.plist (NSPhotoLibraryUsageDescription).
## Recommendation: A
Typographic is the cheapest, loads instantly, and reads fastest; its P2 shows one real result (the reward) which sets up 3d. B has the best moment but the highest build and drop-off risk if the motion stalls; C is clear but dense. Ship A, and borrow B's sorted ticket stack for the first-run Timeline later.
